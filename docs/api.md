# JavaScript API

```bash
npm install @dsebastien/music-notation
```

## Render a block

```ts
import { renderBlock, injectStyles, isNotationLanguage } from '@dsebastien/music-notation'
import { lookupGuitarVoicing } from '@dsebastien/music-notation/voicings'

injectStyles(document)
const result = renderBlock('chord', 'Am', container, { voicings: lookupGuitarVoicing })
```

`renderBlock(language, source, host, options)` appends a `div.mn-block` to `host`, never throws, and returns:

| Field       | Meaning                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| `ok`        | Whether it rendered.                                                                                                     |
| `el`        | The block's container.                                                                                                   |
| `error`     | The message shown when `ok` is false; for several diagrams, each failing one's (`diagram 2: …`), the others still drawn. |
| `destroy()` | Removes the container.                                                                                                   |

Options:

- `voicings`: finds guitar voicings for chord blocks that only give a symbol. Pass `lookupGuitarVoicing` from `@dsebastien/music-notation/voicings` (about 1,800 voicings by symbol, ~230 KB; each one checked against its chord's notes and bass, with the standard teaching shapes first), or your own `(symbol, index) => FrettedVoicing | null`.
- `transpose`: semitones added to `chords` blocks.
- `chartDiagrams`: the chords used row of `chords` blocks when a chart has no `{diagrams}`: `'top'`, `'bottom'` or `'off'` (the default). Guitar or piano follows `instrument`, else the note's tags (`properties`), else guitar; a chart's `{instrument}` wins.
- `orientation`: the default per block language, `{ chord, keyboard, fretboard }`, each `'vertical'` or `'horizontal'`. Piano chords follow `keyboard`. A block's own `orientation` wins.
- `hand`: `'left'` mirrors guitar chords and fretboards unless a block says `hand: right`.

- `properties`: the note's properties, or a function of the block's element returning them (read at each render): an empty `chord`, `fretboard` or `keyboard` block draws from them. `propertyNames` renames them; `instrument` (`'guitar'` or `'piano'`) overrides the one read from the tags.

`layoutDefaults(value)` keeps only valid `orientation` and `hand` values from untrusted input (a page's settings). `MAX_DIAGRAMS` is the most diagrams one block may hold (32).

Everything is created in `host.ownerDocument`, so popout windows work.

## Renderers and theory

- `renderGuitarDiagram(doc, voicing, options)`, `renderKeyboard(doc, noteSet, options)`, `renderFretboard(doc, noteSet, options)`, `renderChart(doc, song, options)`. The diagram renderers take `orientation`, and guitar diagrams and fretboards take `hand`.
- `keyRangeOf(noteSet)`: the keys `renderKeyboard` shows without `range`: a scale's two octaves from its tonic to its tonic (tonic from G3 to F#4), whole octaves around exact pitches, else C4 to B5. Without `range`, `renderKeyboard` lights a scale's keys from the tonic to the top tonic only.
- `parseOrientation(text)`, `parseHand(text)`: read a block's value or throw a message for the user.
- `parseChordName(text)`: a chord name in words (`F Sharp Minor 7`) as a parsed chord; `readChord(text)` takes a symbol or words; `suggestChords(text)` says what to write instead.
- `generateVoicings(symbol, options)`: every playable voicing of a chord, easiest first: `{ frets, fingers, baseFret, bassString, inversion, shape, difficulty, reasons }`. Options: `tuning`, `area` (`[5, 9]` or `'open'`), `bassString` and `strings` (1 = the highest string), `inversion` (the chord's note in the bass, 0–3, or `'any'`; any by default on re-entrant tunings), `maxSpan` (4, at most 6), `allowOpen`, `minStrings`, `gaps`, `maxFret` (15). Up to `MAX_GENERATED_STRINGS` (8) strings.
- `fingerVoicing(frets)`: the easiest fingers for frets (the index or the ring finger may barre a few strings on one fret, the pinky the two highest strings as in E6/9 `022122`, only the index across strings fretted higher, at most four), null when a hand can't play them. `voicingShape(frets, symbol, tuning?)`: `Open`, `C shape`, `A shape`, `G shape`, `E shape`, `D shape` (CAGED shapes, with a barre or not), `Power chord`, `Triad`, `Shell`, or null; a 4th `fingers` argument (0.8.0) is still accepted and ignored. Before 0.9 the barre E and A shapes were `E-shape barre` and `A-shape barre`, the others `CAGED E`…: tell them apart with `isBarreVoicing({ frets, fingers })` (a finger on two strings or more at one fret, the old rule; `reasons.includes('barre')` on a generated voicing says the same) or `barreKind({ frets, fingers })`: `'full'` (over four strings or more, or over strings fretted higher: F 133211, the barre chord), `'partial'` (F xx3211, the A shape's ring-finger barre x3555x) or null.
- `triadVoicings(chord, { strings, inversion, tuning })`: close triads on a string set, up the neck, with their `inversion` and `top` note (R, 3, 5); `keyTriads(key, { strings, inversion })`: a key's seven triads with their numerals; `parseKey(text)`, `inversionName(n)`.
- `transition(fromFrets, toChord, { tuning, fromFingers })`: the next chord's voicings, easiest to reach first, with `anchors`, `guides` (string indexes), `shift`, `movement` and `tips` in plain words; `smoothProgression(chords, { tuning, voicings })`: the voicings that make a progression easiest, standard shapes near the nut first; pass `lookupGuitarVoicing` (from `/voicings`) as `voicings` to prefer the database's shapes.
- Playback: `sequenceOf(kind, pitches, { bpm, strum, root, tones, sound })` (the notes a chord or scale plays, timed, with velocities: `root` is the tonic's pitch class a scale starts on, `tones` the pitch classes of a chord over the scale, `sound` the instrument's touch on chords), `scaleRun(pitches, root)` (the order a scale plays: tonic, top, bottom, tonic), `DEFAULT_STRUM` (`{ guitar: 12, piano: 0 }` ms), `lightPlayer(window, random?)` (the light synthesizer, each note a little different: `pluckedString(midi, sampleRate, seconds, random, { brightness, pick, damping })`, `pianoTone`), `attachPlayback(el, options)` (the bar). The `play` render option (`true`, or `{ player, sound, volume, bpm, strum }`; `strum` defaults to 12 ms on guitar, 0 on piano) adds the bar to every diagram; `player` is a `NotePlayer` or a function returning one at each play, given the diagram's window (popouts have their own). While a diagram plays, each sounding note's `data-midi` element gets the `mn-playing` class. A `NotePlayer` gets `onStart` in its play options: call it when the notes really start sounding (after loading a soundfont, for example), and set `reportsStart: true` on the player so the bar waits for it. Without `reportsStart`, the bar lights notes from the first `onStart` call, or 300 ms after the play call when none comes; a wrapper that passes the options through to `createSoundfontPlayer` or `lightPlayer` gets `onStart` for free (both report it), and once it has been seen calling it, every bar of the page (diagrams and strumming patterns, loops included) waits for it like for a player with `reportsStart`. `noteTargets(drawing, events, kind)` and `followNotes(window, drawing, targets, events, wait)` light notes for your own players (`noteTargets` matches `data-midi`, or the pitch class in `data-mn-chroma`, as on the circle of fifths' chords).
- Strumming patterns: `parseStrum(text)` (a `strum` block's pattern: slots with their stroke, accent, ghost and chord change, the time signature, subdivision, tempo; throws the block's message), `formatStrum(pattern)` (one symbol a slot: `[G]D - D U - U D U`), `renderStrum(doc, pattern, options)`. `playStrum(pattern, { bpm, chord, tuning, countIn, loop, player, window, sound, volume, onEnd, voicings })` plays a pattern (text or parsed) and returns `{ stop() }`: `chord` is a symbol or the notes to strum (lowest string first), `tuning` a name or open-string pitches; the light synthesizer of `window` unless a `player` is given. `strumEvents(score, { bpm, countIn, tail })` gives the timed notes of one pass, `scoreOf(pattern, voicing)` each slot's notes, `strumVoicing(chord, tuning, voicings)` the notes a strum of a chord sounds (E minor without a chord). A `NoteEvent` may carry a `velocity` (1–127, 100 when absent): the light synthesizer scales the note's level, the soundfont player passes it to alphaTab. It may also carry a `kind`: `'muted'` (a dead string, as in a muted strum's chuck) or `'click'` (a metronome tick, `midi` 84 or higher for a strong beat); both players render them as percussive sounds, and players that don't know `kind` play the note as written. `parseSwing(text)` and `isCompound(beatsPerBar, beatUnit)` read `swing:` and compound time; `strumVelocity(slot, up, inBar, slotsPerPulse, seed)` is how hard a strum is played (`STRUM_VELOCITY`, `STRUM_STRESS`); `tempoOf(bpm, compound)` the tempo with its default (90, or 60 in compound time). A pattern's `compound`, `slotsPerPulse` (slots in the counted beat: three 8ths in 6/8) and `swing` (where a pair's second slot falls, 2/3 for a triplet swing, or null) also go in a `StrumScore`. `strumEvents` takes a `seed` (the loop's pass number) for the small differences between strums. Each drawn slot is a `g[data-mn-beat]` (its index from 0) with `data-mn-stroke`, so a page can light the strum that plays.
- `detectChordFromFrets(frets, tuning?)`, `detectChordFromPitches(midis, names?)`: the chord played, `{ symbol, readings }`. With `names` (the notes as written, `['Db3', 'F4', 'B4', 'Eb5']`), the name follows their spelling: Db9, not C#9; G B F Ab Eb is G7b9b13.
- `scaleName(text)` (the usual names as tonal knows them), `modesOf(scale)`, `scaleTypes()`, `characteristicIntervals(type)`.
- `scalePosition(noteSet, tuning, 'box' | 'caged' | '3nps', n, { within, numbering })`: the notes of one position, `{ string, fret }[]`, in its lowest octave (or the lowest one inside the `within` frets). `numbering: 'minor'` counts a major pentatonic's positions from its relative minor. `neckPositions(noteSet, tuning, system, numbering?)`: every position in neck order. Also `positionCount(noteSet, system)` and `MAX_FRET` (36, the highest fret a fretboard draws).
- Arpeggios: `scalePosition` and `neckPositions` take a chord's note set too (`chordNoteSet('Am7')`, system `'caged'`): the chord tones of each CAGED shape. `isArpeggio(noteSet)` tells a chord's notes from a scale or a list.
- `blockFromProperties(language, properties, { names, instrument })`: a block's source from a note's properties; `DEFAULT_PROPERTY_NAMES`, `instrumentOf(properties, names)`.
- `renderChart(doc, song, { transpose, diagrams, instrument, voicings, orientation, hand })`: `diagrams` places the chords used row (`'top'`, `'bottom'`, `'off'`) when the song has no `{diagrams}`. `chordsUsed(song)`: the chords of the lyrics as written, in order of first appearance. With `{capo}`, guitar diagrams (row and `{chord}`) are the shapes played, piano diagrams the chords that sound. `parseDefinition(text, earlier)`: a `{define}` value as `{ definition, problems }`; a song's are in `song.definitions`, and the directives it couldn't read in `song.warnings`.
- `parseChordPro(text)`, `parseFrets(text)`, `parseFingers(text)`, `parseTuning(text)`, `parseKeyRange(text)`.
- `parseChord(symbol)`: root, quality, bass and an ASCII name (`F Sharp Minor 7`).
- `transposeChord(symbol, semitones, spelling?)`, `transposeKey(key, semitones)`, `keyPrefersFlats(key)`. `spelling` is `true` (flats), `false` (sharps), or a `KeyMove` `{ from, to }` (two tonics) from `keyMove(key, semitones)`: notes then move by the interval between the keys and keep their letters (G down a semitone is F#: F#dim becomes E#dim, C becomes B; Em to Ebm turns C into Cb).
- `pianoVoicing(symbol, { inversion, octave, voicing, rootless, shell, hands })`: a piano chord's keys, `{ pitches, left, right, style, inversion, hands }` (MIDI, low to high). `voicing`: `'close'` (default), `'open'`, `'shell'` (`shell: 'R-3' | 'R-7'`) or `'rootless'` (`rootless: 'A' | 'B'`; also half-diminished chords, with the natural 9th); `hands`: `'left+right'` (the bass in the left hand), `'left'` or `'right'`; `octave` is the lowest right-hand note's (4; 3 for rootless voicings). The right hand doesn't double a bass that is the third or the seventh, nor the root of shell, open and rootless voicings with `hands: 'left+right'`. Null for an unknown chord; throws an Error that says what to write when an option doesn't fit (an inversion past the chord's notes, a shell without a seventh). `triadFingering(voicing)`: the usual fingers of a close triad, or null. `standardScaleFingering(tonic, type, hand)`: the method-book fingering of a major or harmonic minor scale (`type` as tonal names it, `hand` `'right'` or `'left'`), one octave going up as 8 fingers, or null; `scaleFingers(pitches, root, chromas, octave)`: a Map of MIDI to finger for every scale key of a stretch of keyboard, the root between two octaves on the thumb. `pianoPitches(symbol, options)`: the same as a note set for `renderKeyboard` (rootless voicings add their 9th and 13th to it). `renderKeyboard` takes `hands` (a Map of MIDI to `'left'` or `'right'`).
- Capo: `renderGuitarDiagram` and `renderFretboard` take `capo` (a fret) and `fretsFrom` (`'capo'`, the default: frets count from the capo, drawn where the nut is; `'nut'`: the real neck); `renderGuitarDiagram` also takes `sounds` (the chord it sounds, for the caption) and `caption: false` (no caption, for a row with one caption of its own; the bar and the sounding pitches stay). `soundingChord(shape, capo)` names the chord a shape sounds (`A` with a capo on 2 is `B`, spelled for its key), `soundsLike(chord, shape, capo)` checks one, `fretsFromCapo(frets, capo)` turns frets from the nut into frets from the capo, `capoTuning(tuning, capo)` gives what the open strings sound; `parseCapo`, `parseFretsFrom`, `capoCaption(capo, sounds?)`, `MAX_CAPO` (12).
- `chordNoteSet(symbol)`, `scaleNoteSet(name)`, `listNoteSet(text, root?)`: the notes, root, degrees and intervals that keyboards and fretboards draw (a list's intervals count from `root`).
- `findScales(notesOrChords, { as, maxOutside, limit })`: the scales that hold some notes or the notes of some chords, best first, each `{ name, tonic, type, notes, missing, outside }` (`missing`: scale notes not played; `outside`: notes played that aren't in the scale). `as` is `'notes'` or `'chords'`; by default a list of plain note names is notes, and so are notes with octaves (`C4 E4 G4`) unless every one could be a power chord (`A5 D5 E5`) or a seventh chord (`A7 D7 E7`); anything else is chords. Up to `maxOutside` (1) outside notes, `limit` (20) scales. A usual scale with exactly the notes given comes first (`C D E G A`: C major pentatonic); over a blues, the blues scale, the minor pentatonic and the mixolydian come first whatever their outside notes.
- `findKey(chords)`: the likeliest key of a progression, `{ tonic, mode, name, score, outside, candidates, clear, blues?, modal? }`; `clear` is false when another key scores about as well (`candidates` lists them). The first chord counts most, then the last one and V7 → I moves. `blues` is true for a dominant-seventh blues on the key's tonic (`A7 D7 E7 A7`: A major); `modal` is the mode the chords play in when it isn't plain major or minor (`Dm C G`: D dorian; `C Bb F C`: C mixolydian). `bluesTonic(chords)`: the tonic of a dominant-seventh blues (`'A'`), or null. `BLUES_SCALES`: the scales `findScales` puts first over a blues (blues scale, minor pentatonic, mixolydian). `inKey(chord, key)`: whether every note of a chord is in a key (a minor key's V and vii° count).
- `scalesForChord(symbol)`: the scales on a chord's root that hold all its notes, best first (`Cmaj7`: C major, C lydian…; `Dm7`: D minor, D dorian, D phrygian…). `chordsInScale(scale)`: each note's triad and seventh chord stacked in thirds (seven-note scales) with the triad's numeral, and every common chord whose notes are all in the scale.
- `progressionChords(numerals, key)`: roman numerals (`I V vi IV`, `ii7 V7 Imaj7`, `bVII`, `V/V`, `I/3`), Nashville numbers (`1 5 6m 4`) or chord names in a key, each `{ written, symbol, numeral, nashville, function }`; null when the key or a chord doesn't read. `readNumeral(numeral, key)`: one numeral's chord symbol. `numeralOf(symbol, key, 'roman' | 'nashville', options?)`: a chord's numeral (`D7` in C is `V7/V`, `F#dim7` is `vii°7/V`). `harmonicFunction(symbol, key, options?)`: `tonic`, `subdominant`, `dominant`, `secondary dominant` (leading-tone diminished chords included), `neapolitan` (bII), `borrowed` or `chromatic`. `options.blues` reads a dominant seventh on I or IV as the key's own chord (A7 is `I7`, tonic, in an A blues); `progressionChords` sets it when the chords are a blues on the key's tonic (`isBluesIn(symbols, key)`).
- `voiceLead(symbols)`: piano pitches for each chord, each in the close-position inversion that moves least from the one before. `voiceLeadVoicings(symbols, { voicing, form, octave, hands })`: shell or rootless voicings for each chord, `{ options, pitches }` (the `pianoVoicing` options with the form and octave chosen), the forms alternating so the chords move least around middle C; null for a chord that can't take the voicing. `voiceMotion(a, b)`: the movement between two chords, each note moving to its own note (semitones).
- `renderCircle(doc, { key, sevenths, neighbours, dominant, title })`: the circle of fifths for a key (`readKey('E minor')`). `dominant`: a minor key's `'major'` V (default, from the harmonic minor) or `'minor'` v.
- `readKey(text)`: `G`, `Em`, `F# minor`, `D dorian` as `{ tonic, mode, name }`; `keyNotes(key)`, `keySignature(key)` (`{ count, accidentals }`: F# major is 6, F# C# G# D# A# E#), `keyChords(key, sevenths?)` (the seven chords with their numerals), `parentMajor(key)`, `signatureText(count)`, `MODES`. `keyProblem(key)`: null, or why a key can't be written (more than `MAX_SIGNATURE`, 7, sharps or flats) with its other name (`Gb minor needs 9 flats: write F# minor`); `readKey` accepts such keys, the blocks refuse them.

## Styles

`injectStyles(document)` adds the stylesheet once; or ship `@dsebastien/music-notation/music-notation.css`. Colors use CSS variables (`--mn-accent`, `--mn-root`, `--mn-fg`, `--mn-muted`…) that default to Obsidian's theme variables, with fallbacks elsewhere. Override them on `.mn-block`.

## Browser bundle

`dist/music-notation.publish.min.js` renders every notation block on the page and exposes the API (plus `lookupGuitarVoicing` and `stop()`) as `window.MusicNotation`. It reads `window.musicNotationOptions` (`orientation`, `hand`) when the page sets it before loading. See [Obsidian Publish](publish.md).

## Tabs and scores

`@dsebastien/music-notation/tab` draws `tab` and `score` blocks with [alphaTab](https://alphatab.net) (MPL-2.0). alphaTab isn't bundled: pass its module (the UMD build, `window.alphaTab`), the music font and the soundfont.

```ts
import { renderTab } from '@dsebastien/music-notation/tab'

const result = renderTab('tab', source, container, {
    alphaTab: window.alphaTab,
    assets: {
        scriptFile: null,
        font: 'https://…/Bravura.woff2',
        soundFont: 'https://…/sonivox.sf3'
    },
    resolveFile: async (link) => bytesOf(link) // for file: [[Song.gp]]
})
const { ok, error } = await result.ready
```

- `scriptFile`: a same-origin URL of alphaTab's script to render and play in workers; `null` works on the main thread. `soundFont` may be bytes. Pass the module of the window the block is in: objects alphaTab checks with `instanceof` are made there, so popout windows work.
- `renderTab` never throws. `ready` settles once and never rejects: `{ ok, error }` when drawn or failed (the message is also shown in the block), `{ ok: false, error: null }` when destroyed first. `result.api` is alphaTab's API once made (`onApi` is called then); `result.destroy()` frees alphaTab, its player and the element.
- `player: false` leaves out the player bar. With the bar, the player (audio, synthesizer, soundfont) starts at the first Play; when it can't, the score stays and Play is disabled with the reason.
- `printTab(result)`: prints a drawn score in black on white, whatever the theme (throws when it isn't drawn yet).
- `parseTabSource(language, source)`: the block's `staves`, `file`, `tracks` and alphaTex.
- `soundfontPlayer(alphaTab, () => api)`, `createSoundfontPlayer(alphaTab, assets, document, fallback)`: a `NotePlayer` for the diagrams' playback through alphaTab's soundfont. alphaTab only loads the instruments its loaded song uses, so the api you give `soundfontPlayer` needs a song with guitar (program 25) and piano (program 0) tracks, and muted guitar (program 28) for muted strums; `createSoundfontPlayer` loads one itself. `createSoundfontPlayer` makes its own hidden alphaTab instance at the first play (the first notes wait for the soundfont), plays through `fallback` (for example `lightPlayer(window)`) when the soundfont can't load, and has `destroy()`.
- `hideDefaultDynamics(score, tex)`: hides the forte alphaTab gives every beat (its "f" on every staff) unless a beat has another dynamic or the alphaTex (`tex`, null for a file) writes one. `renderTab` calls it on every score.
- `scoreToAlphaTex(alphaTab, bytes)` (Guitar Pro 3–8, MusicXML, Capella), `exportGp7(alphaTab, music)`, `exportMidi(alphaTab, music)` (alphaTex or file bytes); `textTabToAlphaTex(text)` (null when the text has no tab; reads bar lines, repeat signs, two-digit frets (10 to 24: `65` is 6 then 5), bass, 5- and 7-string tunings, strings numbered `1|`, short excerpts on the strings they show, drum tabs as a percussion track, text after the last bar line as an annotation (`| let ring`, `|<-- let ring`, `|x2`), and blank staves as empty bars; techniques: bends `7b9` / `7^9` with release `r` (`8b10r8p5` is one bent note, then a pull-off), hammer-ons `h`, pull-offs `p`, slides `/` `\` `s`, vibrato `~` `v`, dead notes `x`, natural harmonics `<12>`, a `PM---` line above the tab; durations from the spacing: each bar a 4/4 bar, its notes on the coarsest grid (whole notes to sixteenths) their columns fit, else the most frequent gap as an eighth and rests to the end of the bar) and `chordSheetToChordPro(text)` (chords over lyrics, labeled chord lines such as `Intro: G D Em C`, repeat marks and N.C.) for pasted text (also in the main entry's converters).
- `alphaTabCdn(version)`: jsDelivr URLs of alphaTab's script, font and soundfont; `ALPHATAB_VERSION`.
