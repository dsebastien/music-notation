# 2026-11-17

## Guitar choice: steel, nylon, clean, overdrive (#103, first part)

- Asked through Music Practice #108 (a guitar sound setting): every diagram played a steel-string acoustic (program 25). #103's first item, without its effects chain (reverb, amp, limiter), which stays open.
- `src/playback/guitar-tone.ts` (`GUITAR_TONES`, `guitarToneOf`, `GUITAR_PROGRAMS`, `blockGuitar`, `guitarWish`, `pageGuitar`) and its spec. `PlayOptions.guitar` (a value, or a function read at each play), the block's `guitar:` line (`{guitar: …}` in a chart), the page option `play: { guitar }`.
- Decisions:
    - Not a new `Sound`: `Sound` stays guitar or piano, because it also says which instrument a diagram is drawn for. The guitar is one more option of a play (`NotePlayer.play` options `guitar`, optional).
    - One place gives it to the players: `playerFor` returns a twin of the player that adds the guitar to each play (`toned`). No bar changed. When nothing names a guitar the app's own player is returned, so existing apps see no difference.
    - Tabs and scores are not touched: their tracks name their instruments.
    - The bar's sound menu still says Guitar and Piano. Listing the four guitars there is left for a later step.
- Players: the soundfont players send the guitar's program (25, 24, 27, 29) and, with instrument files, read that guitar's file at its first use (the muted strings once); the hidden instance's song has a track per guitar, so alphaTab loads their presets from a whole soundfont too; the sample player reads the program's file and gives its fallback the same guitar; the light synthesizer has pluck ranges per guitar and a `drive` for the overdriven one.
- Found by the specs: none. One existing spec changed on purpose: the hidden song's programs (0, 25, 28 became 0, 24, 25, 27, 28, 29).
- English texts and the default sound are unchanged (the steel string's ranges and random draws are the same).
- Checked in headless Chrome with the built bundles (a local page, the GeneralUser GS folder of the sounds package on jsDelivr), by the files each Play fetched, no error on the page:
    - Without a tab (the sample player): a plain chord fetched `index.json` and `p025.sf3`; a chord with `guitar: nylon` fetched `p024.sf3`; a strumming pattern with `guitar: overdrive` fetched `p029.sf3`; a keyboard with `guitar: nylon` fetched `p000.sf3` (the piano); `guitar: banjo` showed its message in the block.
    - With a tab on the page (alphaTab's player) and the page option `play: { guitar: 'clean' }`: a plain chord fetched `p027.sf3`, `p028.sf3` and `click.sf3`; a chord with `guitar: nylon` fetched `p024.sf3` alone; with `engine: sonivox` it fetched `sonivox.sf3`; with `engine: light` nothing.
- `tsc`, `lint`, `build` pass. `bun run test`: 1,445 pass, 1 fail on this machine while it was under load (a timing spec of the text tab converter, "joins bars across many rows in linear time"); the converter's specs pass when run alone (57 pass).
- Not checked: the sound by ear (headless Chrome has no audio; the four guitars of the light synthesizer most of all), Obsidian, a phone.
- The light synthesizer's guitars, measured (the pluck alone, rendered in Bun at 48 kHz, each guitar's middle values), because nobody heard them yet. First version: the overdriven guitar's first tenth of a second was 4 to 6 dB louder (RMS) than the steel string's, and the nylon string was hardly different from the steel one on low notes. Changed: the overdriven peak 0.3 became 0.18 (now within 1.5 dB of the steel string at the start, from the low E to the high E; it stays louder later, which is what overdrive does); nylon is darker and fades sooner (brightness 0.05 to 0.25, damping 2.2 to 2.8: 40 % fewer zero crossings than steel in the first 100 ms, and 6 to 21 dB lower after two seconds from E3 up).

## The guide and a Content Security Policy; 0.24.0 notes

- The API page said the styles pass a strict Content Security Policy. Not on web pages: the stylesheet is an injected `<style>`. The guide now says so (API, Publish, Websites and apps) and gives the other way: link `dist/music-notation.css` with the id `music-notation-styles`, since `injectStyles` adds nothing when that id is there. That behavior was in the code without a spec: `src/styles.spec.ts` now holds it, and Business Rules names the id as API.
- Tried by the ghostwriter in headless Chrome under `style-src 'self'`: with the link every diagram style applied and no `<style>` was added; alphaTab's own styles and music font were still blocked, so pages with tabs keep `'unsafe-inline'`.
