# 2026-10-28

## Done

- Repo created with the plugin template's tooling (Bun, TS, ESLint type-checked, Prettier, commitlint, config-based hooks), adapted to a library: no Obsidian rules, scope `lib`, npm entry points.
- Theory: chord symbol parsing moved from the Music Practice plugin; pitch classes, scientific pitch, transposition with key-aware spelling, note sets (tonal) with degrees and musician-style interval labels.
- Blocks: `chord` (guitar diagram with barres, base fret, root marks, tunings; piano chords from symbols or pitches, fingering), `keyboard`, `fretboard` (tunings, open strings, inlays), `chords` (ChordPro subset, sections, transpose).
- Voicings: chords-db lookup (sharps/flats, aliases, slash chords) behind `./voicings`.
- Publish: `renderAll` / `autoRender` (idempotent, MutationObserver, source hidden only on success) and the IIFE bundle (255 KB, most of it voicing data).
- Checked in Obsidian (dark theme) through the bundle: fixed black piano keys following the text color, and interval labels (3m → b3).
- Docs: README, GitHub Pages guide (blocks, Publish, API), business rules, architecture, plans.

## Decisions

- Two steps: 0.1 light blocks (→ Music Practice 0.2), 0.2 alphaTab (→ Music Practice 0.3).
- No ChordPro library: the maintained ones are GPL.
- Voicing data in its own entry point.
- Piano keys keep fixed white/black colors in every theme.
