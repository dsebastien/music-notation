# Business Rules

- **Block languages**: `chord`, `chords`, `keyboard`, `fretboard` (0.1); `tab` and its alias `score` (0.5). Fence names are stable API: never rename one.
- **Block syntax**: `key: value` lines, keys case-insensitive, last value wins; an optional first line without a key is the block's shorthand. Any other line without a key is an error.
- **Empty blocks** (only whitespace) render nothing, successfully: templates scaffold empty blocks.
- **Errors**: a block with a mistake renders an inline message (what's wrong and what to write) and never throws. On Publish its source stays visible.
- **Publish**: blocks are rendered once (`data-mp-rendered` on the `<pre>`: `pending`, `done`, `error`); the source `<pre>` is hidden only after a successful render; the page is watched (MutationObserver, one pass per frame) because Publish swaps content as you navigate.
- **Chord symbols**: `♯`/`♭` are read as `#`/`b`; a slash starts a bass only when a note name follows (`C6/9` has no bass). Suffix spellings are mapped to one canonical form (`theory/suffix.ts`: Δ7/M7 → maj7, min6 → m6, ø7 → m7b5, m(maj7) → mMaj7, alt → 7alt…) before tonal and the voicing data see them, so every symbol the parser accepts also draws. Alterations and additions in whole groups of parentheses read like the same symbol without them (`C7(b9)` = C7b9, `C7(b5,#9)` = C7b5#9, `Cm(add9)` = Cmadd9), for the quality name too, after the written suffix (`C-(maj7)` keeps its own name); unbalanced or empty parentheses and commas outside a group are not a chord (`C,`, `C()`); the root and the type reach tonal apart, so a group starting with an accidental never changes the root (`C(#5)` = Caug, `C(b9)` is no chord, not C♭9); chord-sheet spellings tonal knows under another name are mapped (#5 → aug; -5 and (b5) → Mb5 "Major flat 5", maj7b5 → M7b5, mmaj9 → mMaj9, m6/9 and m6add9 → m69 "Minor 6/9", sus2sus4 → sus24). A flat root stays a root: `Cb5` is a C♭ power chord. `parseChord` accepts any other chord tonal knows, with its suffix as the quality.
- **Voicing lookup** (`voicings` entry): a symbol's n-th voicing from chords-db; canonical suffixes reach it under its own names (major, minor, mmaj7, mmaj9, maj7b5, alt, 69); a chord it doesn't have (Cmaj9#11, C7b5#9, Csus2sus4…) gets the generator's 4 easiest voicings, cached per symbol (the last 64) and handed out as copies (a block's position changes its base fret).
- **Guitar chords**: frets and fingers are listed lowest string first; `x` = muted, `0` = open; the first fret shown is 1 when every fretted note is within frets 1–4, else the lowest fretted fret; `position` overrides it but can't be above the lowest fretted note; a finger on the same fret across 2+ strings is a barre. The chord's root is marked when the tuning is known (6 strings default to standard); an unknown symbol with frets still renders, without root marks.
- **Piano chords**: from a symbol, root position stacked upwards from middle C (C4 = MIDI 60); a slash chord's bass (matched by pitch, not spelling) an octave below; `fingering` maps to keys low to high.
- **Note sets** (keyboard, fretboard): from a scale, a chord, or a list; a list with octaves highlights those exact keys, otherwise every octave. A shorthand line is tried as scale, exact notes, chord, then list. The root (scales, chords) gets its own color. Degrees: a chord's interval numbers (1 3 5 7), a scale's positions. Interval labels are written the way musicians do (R, b3, 3, #4, b7). `labels: fingers` only exists for piano chords with fingering.
- **Keyboard range**: two octaves from middle C by default; whole octaves around exact pitches; a range never starts or ends on a black key. A scale's `fingering` covers one octave from the root: without a range the keyboard shows that octave (middle C's); with one, every octave stays lit and the fingering starts on the first root inside the range (else the one below it). With a `labels:` other than fingers, the labels stay on the keys and the fingers get their own row past the keys' near end.
- **Fretboard**: high string on top (tab convention); frets 0–12 by default; up to fret 36.
- **Several diagrams** (`chord`, `keyboard`, `fretboard`; never `chords`): lines of only `---` (3 dashes or more) separate diagrams; empty parts are skipped. The first part holds shared settings when it has no shorthand line and only shareable keys (`orientation`, `hand`, `labels`; chord: `instrument`, `tuning`, `range`; keyboard: `range`; fretboard: `tuning`, `frets`) plus `columns` (1–12, a grid of at most that many columns that wraps on narrow screens; only there). A first part with `columns` is always the shared settings: any non-shareable key there is an error naming it. Precedence: the diagram's non-empty key, the shared one, the render options' default (normalized: invalid values ignored, any case), the language default. Shared `orientation` / `hand` are checked once for the block. A block of only separators draws nothing. Diagrams are capped at 12 strings and 88 keys. A diagram with a mistake shows its message in its cell, the others draw, and the block is not ok (Publish keeps its source visible). At most 32 diagrams; shared settings with no diagram are an error.
- **Orientation and hand**: chord diagrams are vertical by default (nut on top, low string on the left); fretboards horizontal (high string on top, nut on the left); keyboards horizontal (low notes on the left); vertical keyboards have their low notes at the bottom and black keys on the left. Piano chords follow the keyboard default. `hand: left` mirrors guitar diagrams and fretboards; keyboards ignore it (the value is still checked). Text is never rotated or mirrored. A title wider than its diagram widens and centers it.
- **Chord names in words**: read wherever a symbol is (`symbol:`, `name:`, the shorthand), the reverse of `parseChord().name` (round trip), any case; with a space the words reading wins (`E 5` is E5), without one the symbol does. The shorthand's chord ends where frets may start (a word starting with x or a digit), at the longest start that reads as a chord. The words stay the title. A chord that doesn't read and has no frets is an error suggesting `A, Am, A7 or A Major`.
- **Generated voicings**: `generateVoicings` and `voicings:` sound every required tone (root, third or sus, sevenths and sixths, altered notes, the highest natural extension; the perfect fifth, lower natural extensions and an 11th chord's major third may be left out), only chord tones, with the bass (a slash chord's, else the inversion's note: the chord's n-th note as tonal lists it; the root by default, any note on re-entrant tunings) lowest by pitch. On three strings or fewer no note is doubled while a tone is missing. Fretted notes stay within 4 frets (5 with a stretch, 6 at most), up to fret 15 by default (or the area's last fret); no muted string between sounding ones unless asked; at least 4 strings (2 for power chords, fewer when fewer are allowed). Fingers (`fingerVoicing`): a search over every split of each fret's notes into single notes and barres (a barre: adjacent strings at one fret, every string under it sounding at that fret or higher; only the index, on the lowest fret, may lie over strings fretted higher), finger numbers going up with the frets (then from the low string), a finger at most one fret past one fret per finger from another, at most 4; cost: fingers, 2.5 per barre (−2 for an index barre on the lowest fret reaching the top string without lying over higher frets), 0.1 per fret away from one finger per fret, 1.5 for two fingers on one fret three strings apart with a finger between on a higher fret (awkward). Ranking (lower is easier): fingers, span, 0.15 × base fret, barre (1 for E-/A-shape barres and small barres of 2–3 strings, else 3), reach (3 frets apart across 2 strings), awkward fingering, stretch, muted strings (inner 2, high 1.5, low 1; not for power chords), outside the usual open chords: open strings far below the frets and open strings ringing inside the shape, a missing fifth; minus 3 for the usual open chords (a fixed list, standard tuning), 2 for E-/A-shape barres, 1.5 for the other CAGED shapes and power chords; ties go to more strings, then lower on the neck. Shapes: power chord, shell (R 3 7/6 only, 3–4 strings), triad (3 adjacent strings, 3 notes), open (open strings, top string sounding, 4+ strings, frets 1–4), then in standard tuning the CAGED shapes (the open C A G E D chord of the same quality slid up by its distance or an octave more, root on that shape's string; E and A with a barre are E-/A-shape barres), other barre. Strings in options and blocks count from the highest (1). Up to 8 strings; `voicings:` draws at most 32, refuses frets, fingers, `voicing`, `position`, `base` and piano keys (and frets in the shorthand), titles each diagram with the block's title (or the chord) and the shape, reads `area: 0-…` from fret 1, on 7–8 strings allows one of gaps, stretch and a wide area (over 12 frets) and `inversion: any` only with six strings or fewer, says which filter emptied the list, keeps the last 32 lists, and can't sit inside a `---` row.
- **Triads**: close triads only (three adjacent strings, one chord tone each, within four frets counting open strings as 0), for three-note chords (tonal's members with an interval); ordered by their lowest fret, then inversion; `top` is the highest pitch's interval label. `triads:` takes exactly three adjacent strings; `inversion:` 0–2 (all by default; one, 0 by default, with `key:`); a key's triads come from tonal's major or natural minor key, each the first voicing at or above the previous one's lowest fret (up to fret 20), else the lowest; numerals by degree (I–VII), lowercase for minor and diminished, ° for diminished. Triad rows label dots with intervals unless `labels:` is given.
- **Guitar dot labels**: `labels: fingers` (default), `intervals` (the chord member's interval label), `notes` (its name), `none`; intervals and notes need a chord the library knows and a known tuning (6 strings default to standard); open strings have no label.
- **Transitions**: from a held voicing (its fingers, worked out when absent), the next chord's 30 easiest voicings ranked by movement + 0.4 × difficulty. Movement: an anchor (same string, fret and finger) is free; a guide (same string and finger, another fret at most 3 frets away: further, the finger is lifted) costs 0.5 + 0.1 per fret; any other finger 1 (a barre counts once); plus 0.3 per fret the lowest fretted note moves. Tips: anchors, then guides (one per finger), then "Move your hand up/down N frets" from 2 frets, else "Lift all your fingers together…"; string names say low/high when two strings share a name, and use the string's number when three do. `smoothProgression`: each chord's 12 easiest voicings, the sequence with the least total (0.4 × difficulty of the first + each step's score), by dynamic programming. Blocks: `from:` (a chord, words or symbol, with optional frets and fingers; else its easiest voicing) with `to:` and `count:` (3 by default, up to 31), or `progression:` (2 to 32 chords, spaces, or commas or bars); `anchors:` / `guides:` mark strings on any guitar diagram. `to:` without `from:` is an error asking for the held chord; transitions on a non-fretted instrument need a tuning; `triads:` and `voicings:` can't be in one block.
- **Playback**: with the `play` render option, every rendered diagram that has notes (`data-mn-pitches`: a guitar chord's sounding strings low to high when the tuning is known, a keyboard's highlighted keys, a fretboard's dots) gets a bar: play/stop, loop, speed only when several notes play (BPM 20–240 for scales and lists, strum 0–200 ms for chords; values outside are clamped, non-numbers fall back to the defaults), volume 0–100 (sliders as tall as their thumb, the track a centered line: no host or browser offset to correct), sound (its opened list in the page's colors; guitar for guitar diagrams and fretboards, piano for keyboards and piano chords by default). Chords strum low to high and ring 2.5 s; scales go up then down, top once, one beat a note, from the lowest root to the highest one when two roots or more are drawn (notes outside are left out of the run). A click on a `data-midi` element plays it for 1.5 s. The bar shows on hover, focus or a tap (touch). A loop stops when its diagram leaves the page; Publish stops a rendering it replaces. Players: the light synthesizer (Karplus-Strong guitar from one buffer per pitch, made before the start time; piano from oscillators with a struck envelope; one AudioContext per window, made on the first play), or the app's (`player`, also a function read at each play with the window the diagram is in at that moment, so a diagram a host moved to another window plays there). The Publish bundle turns it on (`play: false` off) and uses `window.musicNotationSoundfontPlayer` when set.
- **Tabs and scores**: `tab` / `score` blocks: settings lines first (`staves: tab|score|both`, `file:`, `tracks:`), then alphaTex; `tab` shows tablature and `score` notation by default; all tracks unless `tracks:` names some. alphaTab is passed in, never bundled; colors come from the page's text color once the block is on the page (any CSS color, normalized to rgba through a canvas; black when unreadable); objects alphaTab checks with `instanceof` (Map, Uint8Array) are made in the block's window (popouts); workers only with a script URL (Publish renders on the main thread: cross-origin workers fail). `renderTab` never throws and its `ready` settles once and never rejects (drawn, failed, or destroyed before drawing). The player (audio, synthesizer, soundfont) starts at the first Play, so a note full of tabs costs nothing until one plays; when playback can't start, the score stays and Play is disabled with the reason. `printTab` prints a drawn score in black on white, whatever the theme. Errors show alphaTab's first error diagnostic with its line (offset by the settings lines) and column. A file the host can't find or can't read, or bytes alphaTab doesn't know, is an error naming it. The player bar (hover/tap): play/pause, stop, loop, metronome, count-in, speed 25–150%, volume, time. Exports: Guitar Pro 7 and MIDI from alphaTex or file bytes; imports: score files → alphaTex (alphaTab's exporter), text tabs → alphaTex (string lines are ≥ 4 dashes with a bar line or a string name, so a line of dashes alone is a rule; groups of 4+ lines; every beat an eighth; bar lines and repeat signs `|:` `:|` end a bar; a two-digit fret's partner written one column right on another string is the same beat; tuning written when string names aren't standard guitar; bass names (E A D G, B E A D G) an octave below; without names, 4 strings are a bass, 5 a 5-string bass, 7 a 7-string guitar), chord sheets → ChordPro (chord-only lines merged into the next lyric line at their columns; bar lines, repeat marks, counts (2x, x2) and N.C. allowed among the chords; `Intro: G D Em C` → a comment and its chords; section names → comments; square brackets in lyrics become round, since `[x]` is a chord in ChordPro).
- **Tab bundle** (`music-notation.tab.min.js`, web pages): starts once per page; loads alphaTab, its font and soundfont from jsDelivr the first time a page has a `tab` or `score` block (a failed load keeps every source visible; the next page change tries again); renders on the main thread; marks each `<pre>` like the main bundle (`data-mp-rendered`) and hides it only after a successful draw; redraws a block whose source changed in place, frees blocks that left the page (and shows their source again if it stayed); sets `window.musicNotationSoundfontPlayer` (its own hidden alphaTab instance on the first play, the light synthesizer when the soundfont can't load).
- **Chord recognition**: with no symbol and no chord `name`, frets (in the block's tuning; 6 strings default to standard) or piano pitches name the chord and give its root marks. A chord with a third and a seventh but no fifth is read with the fifth assumed (shells: `3x44xx` is Gmaj7). tonal's readings are spelled as symbols are (M, Madd9, m/ma7, 7add6 → 13, m7add6 → m13, a trailing no5 dropped…) and kept only for common and a few extended qualities; ranked by quality (common first) plus a fixed cost for a slash, then usual root spelling (Bb, F#), then a slash bass spelled as the matching chord tone (C7/Bb, not C7/A#), else with the accidentals of the chord's key. A given symbol always wins.
- **Scales**: tonal names plus aliases (natural minor, blues = minor blues), any case; a scale name without a root is an error asking for one. The altered scale switches to its superlocrian degrees (1P 2m 3m 4d 5d 6m 7m: G# A B C D E F#) when tonal's (b9 #9 3 #11) need a double accidental; other scales keep one letter per degree (G# harmonic minor's 7th is F##). Characteristic notes (lydian 4A, dorian 6M, mixolydian 7m, phrygian 2m, locrian 5d, minor/aeolian 6m, blues 5d, major blues 3m, harmonic minor 7M, melodic minor 6M 7M, phrygian dominant 2m 3M) are marked by default when the written name has a mode word or blues; `highlight:` overrides (characteristic, none, or interval labels, each of which must be in the scale). The root keeps its color. `compare:` (a type, or a scale with its root): own notes not in the other scale outlined, its notes missing here drawn as ghosts. Symmetric scales (chromatic, whole tone) have no modes.
- **Positions**: boxes (2 notes per string from the n-th note on the low string), CAGED for 7-note scales (`position: n` on a 7-note scale means CAGED; the major or minor pentatonic inside, box n, plus the other notes on the string that keeps them closest to the box's frets, the lower string on a tie; scales with no pentatonic inside use 3NPS), 3NPS (3 per string from degree n). E = 1, D = 2, C = 3, A = 4, G = 5. Each position takes the lowest octave where every note is at fret 0 or above. The fretboard shows the position's frets. `positions:` expands into a row (columns and shared keys in a shared part); `modes:` too (ionian and aeolian when the type is exactly major or minor); neither can be used inside a `---` row.
- **Blocks from properties**: an empty chord / fretboard / keyboard block draws `blockFromProperties` of the note's properties when given (an object or a function, read at each render; a failing function draws nothing). Values become one line each (no line breaks, so a value never adds a key); frets and fingers stored as numbers (YAML drops leading zeros) are padded back (6 strings). Reading properties never throws (a failing value draws nothing). The properties function gets the block's element; on Publish the properties are part of the block's fingerprint. Piano from a tag with a `piano` segment unless the host says. `position` 0 or empty is computed; chord shapes (Open…) say nothing for scales.
- **Transposition**: by whole semitones (fractions rounded, invalid values ignored); chords keep their own spelling (sharps or flats) unless a key decides; keys use their usual spelling (F♯ over G♭, D♭ over C♯, B♭m over A♯m).
- **ChordPro**: unknown directives are ignored; `#` lines are comments; tab and grid sections are shown as written. Parsing is linear in the input (no backtracking regexes on user text).
- **Publish re-rendering**: a block is rendered again when its source changed in place (fingerprint in `data-mp-source`) or its rendering was removed; a broken edit shows the source again. The bundle starts once per page even if loaded twice.
- **Licenses**: MIT library; dependencies MIT-compatible, alphaTab (MPL-2.0) unmodified; no GPL. Third-party code shipped inside `dist/` is listed with its license in `dist/THIRD_PARTY_LICENSES.md` (and a banner in the browser bundle).
- **Packaging**: every entry loads in Node and in bundlers (no JSON or CSS imports in `dist/`); types resolve under `bundler`, `node10` and `NodeNext`.
