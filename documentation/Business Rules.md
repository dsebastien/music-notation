# Business Rules

- **Block languages**: `chord`, `chords`, `keyboard`, `fretboard` (0.1); `tab` and its alias `score` (0.4). Fence names are stable API: never rename one.
- **Block syntax**: `key: value` lines, keys case-insensitive, last value wins; an optional first line without a key is the block's shorthand. Any other line without a key is an error.
- **Empty blocks** (only whitespace) render nothing, successfully: templates scaffold empty blocks.
- **Errors**: a block with a mistake renders an inline message (what's wrong and what to write) and never throws. On Publish its source stays visible.
- **Publish**: blocks are rendered once (`data-mp-rendered` on the `<pre>`: `pending`, `done`, `error`); the source `<pre>` is hidden only after a successful render; the page is watched (MutationObserver, one pass per frame) because Publish swaps content as you navigate.
- **Chord symbols**: `♯`/`♭` are read as `#`/`b`; a slash starts a bass only when a note name follows (`C6/9` has no bass). Suffix spellings are mapped to one canonical form (`theory/suffix.ts`: Δ7/M7 → maj7, min6 → m6, ø7 → m7b5, m(maj7) → mMaj7…) before tonal and the voicing data see them, so every symbol the parser accepts also draws. `parseChord` accepts any other chord tonal knows, with its suffix as the quality.
- **Guitar chords**: frets and fingers are listed lowest string first; `x` = muted, `0` = open; the first fret shown is 1 when every fretted note is within frets 1–4, else the lowest fretted fret; `position` overrides it but can't be above the lowest fretted note; a finger on the same fret across 2+ strings is a barre. The chord's root is marked when the tuning is known (6 strings default to standard); an unknown symbol with frets still renders, without root marks.
- **Piano chords**: from a symbol, root position stacked upwards from middle C (C4 = MIDI 60); a slash chord's bass (matched by pitch, not spelling) an octave below; `fingering` maps to keys low to high.
- **Note sets** (keyboard, fretboard): from a scale, a chord, or a list; a list with octaves highlights those exact keys, otherwise every octave. A shorthand line is tried as scale, exact notes, chord, then list. The root (scales, chords) gets its own color. Degrees: a chord's interval numbers (1 3 5 7), a scale's positions. Interval labels are written the way musicians do (R, b3, 3, #4, b7). `labels: fingers` only exists for piano chords with fingering.
- **Keyboard range**: two octaves from middle C by default; whole octaves around exact pitches; a range never starts or ends on a black key.
- **Fretboard**: high string on top (tab convention); frets 0–12 by default; up to fret 36.
- **Several diagrams** (`chord`, `keyboard`, `fretboard`; never `chords`): lines of only `---` (3 dashes or more) separate diagrams; empty parts are skipped. The first part holds shared settings when it has no shorthand line and only shareable keys (`orientation`, `hand`, `labels`; chord: `instrument`, `tuning`, `range`; keyboard: `range`; fretboard: `tuning`, `frets`) plus `columns` (1–12, a grid of at most that many columns that wraps on narrow screens; only there). A first part with `columns` is always the shared settings: any non-shareable key there is an error naming it. Precedence: the diagram's non-empty key, the shared one, the render options' default (normalized: invalid values ignored, any case), the language default. Shared `orientation` / `hand` are checked once for the block. A block of only separators draws nothing. Diagrams are capped at 12 strings and 88 keys. A diagram with a mistake shows its message in its cell, the others draw, and the block is not ok (Publish keeps its source visible). At most 32 diagrams; shared settings with no diagram are an error.
- **Orientation and hand**: chord diagrams are vertical by default (nut on top, low string on the left); fretboards horizontal (high string on top, nut on the left); keyboards horizontal (low notes on the left); vertical keyboards have their low notes at the bottom and black keys on the left. Piano chords follow the keyboard default. `hand: left` mirrors guitar diagrams and fretboards; keyboards ignore it (the value is still checked). Text is never rotated or mirrored. A title wider than its diagram widens and centers it.
- **Chord names in words**: read wherever a symbol is (`symbol:`, `name:`, the shorthand), the reverse of `parseChord().name` (round trip), any case; with a space the words reading wins (`E 5` is E5), without one the symbol does. The shorthand's chord ends where frets may start (a word starting with x or a digit), at the longest start that reads as a chord. The words stay the title. A chord that doesn't read and has no frets is an error suggesting `A, Am, A7 or A Major`.
- **Chord recognition**: with no symbol and no chord `name`, frets (in the block's tuning; 6 strings default to standard) or piano pitches name the chord and give its root marks. Readings are ranked by common quality, then root position, then usual root spelling (Bb, F#). A given symbol always wins.
- **Scales**: tonal names plus aliases (natural minor, blues = minor blues), any case; a scale name without a root is an error asking for one. Characteristic notes (lydian 4A, dorian 6M, mixolydian 7m, phrygian 2m, locrian 5d, minor/aeolian 6m, blues 5d, major blues 3m, harmonic minor 7M, melodic minor 6M 7M, phrygian dominant 2m 3M) are marked by default when the written name has a mode word or blues; `highlight:` overrides (characteristic, none, or interval labels, each of which must be in the scale). The root keeps its color. `compare:` (a type, or a scale with its root): own notes not in the other scale outlined, its notes missing here drawn as ghosts. Symmetric scales (chromatic, whole tone) have no modes.
- **Positions**: boxes (2 notes per string from the n-th note on the low string, at or above the root's fret), CAGED for 7-note scales (the major or minor pentatonic inside, box n, plus the other notes on the lower string when within the box's frets ±1, else the upper; scales with no pentatonic inside use 3NPS), 3NPS (3 per string from degree n). E = 1, D = 2, C = 3, A = 4, G = 5. The fretboard shows the position's frets. `positions:` expands into a row; `modes:` too (ionian and aeolian written as such).
- **Blocks from properties**: an empty chord / fretboard / keyboard block draws `blockFromProperties` of the note's properties when given (an object or a function, read at each render; a failing function draws nothing). Values become one line each (no line breaks, so a value never adds a key). Piano from a tag with a `piano` segment unless the host says. `position` 0 or empty is computed; chord shapes (Open…) say nothing for scales.
- **Transposition**: by whole semitones (fractions rounded, invalid values ignored); chords keep their own spelling (sharps or flats) unless a key decides; keys use their usual spelling (F♯ over G♭, D♭ over C♯, B♭m over A♯m).
- **ChordPro**: unknown directives are ignored; `#` lines are comments; tab and grid sections are shown as written. Parsing is linear in the input (no backtracking regexes on user text).
- **Publish re-rendering**: a block is rendered again when its source changed in place (fingerprint in `data-mp-source`) or its rendering was removed; a broken edit shows the source again. The bundle starts once per page even if loaded twice.
- **Licenses**: MIT library; dependencies MIT-compatible, alphaTab (MPL-2.0) unmodified; no GPL. Third-party code shipped inside `dist/` is listed with its license in `dist/THIRD_PARTY_LICENSES.md` (and a banner in the browser bundle).
- **Packaging**: every entry loads in Node and in bundlers (no JSON or CSS imports in `dist/`); types resolve under `bundler`, `node10` and `NodeNext`.
