# v0.19: export diagrams as SVG and PNG, and Copy as image on the block bar (#11)

Status: built on branch `export-image`.

Goal: diagrams are SVG in the page, but there is no clean way to get them out (a chat with a teacher, a slide, a printout, a post). Apps and pages get two functions that give a standalone image of any drawing or block, and every block bar gets a **Copy as image** button. #83 (the button) was merged into #11 on 2026-11-10.

## Decisions (Sébastien, 2026-11-10)

1. The button copies the selected diagram; the whole block when the block has one diagram. Shift+click copies the whole block.
2. PNG at 2x, in the current theme's colors on the page's background (opaque), titles and captions (`caption: fingering`) included, the bar left out.

## Rules

- `toSvgString(el, { theme?, background? })`: a standalone SVG (`xmlns`, explicit `width` and `height` in CSS pixels as the page lays it out, a `viewBox`) of a drawing (`svg.mn-svg`) or of any element holding drawings and text (a block, a row, a captioned figure, a chart). Every style is inlined from the computed style (no `var(`, no classes, no `data-*`); what doesn't show is left out (`display: none`, `visibility: hidden`, `hidden`, the bars, the hidden name of a playable diagram, marks with neither fill nor stroke such as hit areas); a note lit while it plays is drawn unlit.
- Composition: each drawing is placed at its box on the page (a nested `<svg>` with its own `viewBox`); HTML text becomes SVG `<text>`, line by line where the page wraps it (each line's `textLength` is its width on the page, so another font keeps the layout), `white-space: pre` text keeps its spaces; HTML backgrounds and borders become rectangles. Never `<foreignObject>`: Chrome taints a canvas that draws one, and `toBlob` throws.
- `theme`: `inherit` (default, the page's colors), `light` or `dark` (the library's colors for that theme: the variables it reads, set around a copy of the element). Font families keep the page's list, with `sans-serif` added when the list has no generic family: an SVG drawn as an image can't use the page's web fonts.
- `background`: a CSS color drawn under everything; the SVG has none by default (transparent).
- `toPng(el, { scale = 2, theme?, background? })`: a `Promise<Blob>` (`image/png`): the SVG drawn on a canvas at `scale` (lowered so no side passes 16384 px). Background by default: the first non-transparent background of the element or its ancestors, else white (`#ffffff` with `light`, `#1e1e1e` with `dark`). Works in popouts: the element's document and window are used, never the global `document`.
- The copy is made on a copy of the element, placed out of sight in the element's document (at the element's width, so text wraps as on the page) and removed after.
- **Copy as image** (`.mn-play-copy`, a picture icon like the other bar icons, named "Copy as image", hand cursor): on every block bar (diagrams), the bar of progressions and charts, and the bars of strumming and picking patterns, after the bar's own controls and before the app's (#77). Block bar: the selected diagram with its caption (the drawing shown, also when redrawn for the other instrument), the whole block with one diagram or with Shift. Other bars: the whole block. Not on tab and score bars (alphaTab draws them): later.
- Clipboard: `navigator.clipboard.write([new ClipboardItem({ 'image/png': promise })])` in the window of the bar, called inside the click (the PNG is a promise, so Safari keeps the user gesture). After: "Copied" for 2 s in a polite live region (`.mn-play-said`); a refusal says what to do ("Allow clipboard access for this page, then try again."); no `ClipboardItem` says the browser can't ("This browser can't copy images: use a recent Chrome, Edge, Safari or Firefox."); a drawing that fails says so.
- `PlayOptions.copyImage: false` leaves the button out (apps with their own export).

## Build

1. Specs first: inlined styles and what is left out (SVG), composition with measured boxes (a fake measure: boxes, text lines, font ascent), themes, background, the PNG's size and scale cap, the button's place, target and messages.
2. `src/export/image.ts` (`toSvgString`, `toPng`, and the composition behind a measure), `src/playback/copy-image.ts` (the button), the `copy` icon in `bar-parts.ts`, the button in the four bars, styles for the message.
3. Docs: `docs/api.md` (the two functions), `docs/blocks.md` (the bar), README API list, the playground (Download SVG, Download PNG, shown only when the bundle has them), Business Rules, history.
4. Chrome (headless): a chord with a fingering caption, a row of chords, a progression, a chart, a strumming pattern, a keyboard; copy through the clipboard, the PNG read back; light and dark.
