# v0.16: note names in solfège and German (#12)

Status: built on the branch `naming`, reviewed (findings fixed), not released.

Goal: much of the world reads Do Ré Mi, and German-speaking musicians write H for B. A block (or the app) chooses how names show; input reads all three systems.

## Decisions (Sébastien's brief, 2026-11-08)

1. `naming: letters | solfege | german`: a block key and a render option (the app's default, like the layout defaults; Publish: `window.musicNotationOptions.naming`). The block key wins. Default letters: nothing changes without it.
2. Solfège: Do Ré Mi Fa Sol La Si; accidentals shown as ♯ and ♭ (`Fa♯`, `Si♭`). Chords: the root, a space, the suffix (`Ré m7`, `Sol 7`, `Do`), a bass after a slash in the same system (`Do/Sol`).
3. German: H is B natural and B is B♭ (`H7`, `B` for B♭ major); other notes keep their letters and signs (`F#`, `Eb`).
4. Input reads all three: `chord: Rém`, `scale: La minor`, `notes: Do Mi Sol`, `H7`, `key: Sol`. Accents are optional (`Re` is Ré); `dièse` and `bémol` after a syllable are ♯ and ♭ (`Fa dièse`). `H` is B natural in every system. A bare `B` (no sign) is B♭ only in a block whose naming is german (the block key or the app's default), else B natural, as before.
5. Charts take `{naming: solfege}` (a directive), other blocks a `naming:` line anywhere in the block (it names the whole block, every diagram of a row).
6. Shown in the chosen system: note labels on dots and keys, string names, the titles the library writes and the chord symbols and notes in titles, chart chord symbols, progression chord names, the circle of fifths, the diagrams' names for screen readers (and so the play bar's names).

## Build decisions (taken while building)

7. A solfège syllable reads as a note only when what follows can't make it a word: the end, a sign (`#`, `b`, ♯, ♭, `dièse`, `bémol`), a digit, a space, a slash, a parenthesis or a chord quality start (`m`, `M`, `maj`, `min`, `dim`, `aug`, `sus`, `add`, `+`, `°`, `ø`, `Δ`, `-`). So `[Solo]` in a chart stays text, not Sol with a quality.
8. Scale and mode words stay English (`La minor pentatonic`); `majeur` and `mineur` read as major and minor. Other French scale words: later.
9. Reading: `renderBlock` reads the block's note names into letters before anything parses them (`lettersInBlock`: the values of the keys that hold notes, chords, scales, keys and tunings, the shorthand line, progression lines, chart chords and directives; never strum or picking pattern lines, titles or lyrics). So German B never reaches the library's own code, where B is B natural. Apps get the same reading with `toLetters(text, naming)`.
10. Showing: drawing goes through `shown(text)` at the places that draw names (titles as they wrap, accessible names, dot and key labels, string names, chart chords, progression names, the circle), under a naming that `renderBlock` sets for the block's drawing (`withNaming(naming, draw)`, exported for apps that call renderers). Data attributes (`data-mn-set`, `data-mn-note`, `data-mn-chord`…) stay in letters: apps and playback read them.
11. In titles and names, a token is rewritten when it reads as a chord or a note (with or without an octave). A lone `A` followed by a word that isn't a scale, mode or shape word stays (`A long title`: the English article).
12. Left out: tabs and scores (alphaTab draws its own text), a diagram redrawn by the play bar for the other instrument (drawn in letters), fingering captions (`caption: fingering`: sentences in English with letter names), the `check` command's output. Later if asked.

## Review (fresh agent) and outcome

The review found regressions for notes written in letters and display defects. Sébastien's rule for the fixes: no change for letter content without `naming`. Outcome (Business Rules, Note names, has the details):

- Reading is letters first: what already reads in letters stays (`Do` is D°, `[Do7]`, `[sim.]`, `[Six]`, `[la]` unchanged). `Do` is C only in a solfège block or among other solfège names. Syllables are capitalized; `x` is no sign after a syllable.
- Only the block's own `naming:` line reads; the app's option only shows (an app default never re-reads a B as B♭).
- `H`: B natural in key values, where it was an error; elsewhere only in a block with its own naming line. Charts are read only with their own directive.
- Hand-written titles are never rewritten (also inside a longer name); generated text only. CAGED shapes keep their letters; runs of notes keep their octaves (`C5 E5 G5`); signs as written in German; `D♯m/E♭m`.
- More keys read (`symbol`, `name`, `from`, `to`, `modes`, `scales-for-notes`, `sounds`), circle shorthand, strum and picking `[chord]` changes, compact tunings, chart `{key: La mineur}`, `Sol,Ré`, `|Sol|Ré|`, `La/Do dièse`, NFD accents, the forms the library shows (`Ré m7`, `Sol 7/Si`).
- Messages quote what the user wrote. A wrong chart directive is a warning; the chart draws.
- Shown in the naming too: capo captions, the chart key line, progression notes, strum and picking chord labels; pattern names never (their D strokes stay). The play bar's redraw draws in the block's naming, its title never shown twice.
- Publish: `pageNaming`, with a spec.
- Main and this branch draw 1275 blocks (the specs' blocks, the docs, Music Practice's docs, every block of the vault) the same, except the 2 new doc examples and 2 key values where `H` was an error.
- Left out, documented: German note words, lowercase minor keys, solfège chord lists in generated titles.
