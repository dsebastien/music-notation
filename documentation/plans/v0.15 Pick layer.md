# v0.15: pick layer on fretboards and keyboards

Status: built, reviewed (findings fixed), not released.

Goal: the click layer that Music Practice's drills need (Music Practice #73, its plan `v0.18 Drills.md`, decision 3): every string × fret of a fretboard and every key of a keyboard is a target that a click or the keyboard picks, with its string, fret, note and pitch; the app marks a pick right or wrong on the drawing. Off by default.

## What it is

- A render option: `pick: true` on `renderFretboard` and `renderKeyboard`, and `pick: { onPick }` on `renderBlock` (fretboard and keyboard blocks only). Without it nothing changes: no layer, no attribute.
- The layer is drawn last, above the dots, the inlays and the labels: a `g.mn-picks` with one transparent `rect.mn-pick` per target (`fill: transparent`, `pointer-events: all`, so it takes clicks without the stylesheet). The diagram's root gets `data-mn-pick`.
- Fretboard targets: every string × every fret shown (the open strings when fret 0 is shown); the cell is the hit area's (#69): the string's lane across, the fret along (the open column on fret 0). Frets behind a capo drawn from the nut have no target (nothing sounds there). Every string gets targets, also the ones `strings:` leaves without dots.
- Keyboard targets: every key, the key's own rectangle; black keys come after the white keys, so they are on top where they overlap.
- Each target carries `data-mn-pitch` (MIDI), `data-mn-note` (the pitch class as the drawing spells it: the set's name when the note is in the set, else sharps, or flats when the set prefers flats), and on fretboards `data-mn-string` (1 is the highest string, as the dots) and `data-mn-fret`. Never `data-midi`: playback and note following ignore the layer.
- Where a mark goes: `data-mn-mark-x`, `data-mn-mark-y` (the dot's center on fretboards; near the player's end of a key, where its label goes) and `data-mn-mark-r`.

## Picking (`attachPick`)

- `attachPick(svg, { onPick })` makes a drawn layer live and returns a `PickLayer`. `renderBlock` calls it for each diagram with a layer and frees it in `destroy`. A diagram without a layer returns a layer with no targets.
- A click on a target picks it: `onPick(pick, layer)` with `{ string, fret, note, pitch, element, via: 'pointer' | 'keyboard' }` (`string` and `fret` are null on keyboards). A press on the layer never reaches the host (`pointerdown`, `mousedown` and `click` stop there), so a live preview editor does not open the block's source.
- Keyboard: one target is in the tab order at a time (roving `tabindex`: the last focused or picked one, at the start the first in document order: the highest string's lowest fret, the lowest key). Arrows move the focus: on fretboards to the next target on the screen in the arrow's direction on the same line (so orientation and hand need no special case), on keyboards to the next key up (Right, Up) or down (Left, Down) in pitch. Home and End go to the string's lowest and highest fret, the lowest and highest key. Space or Enter picks. Keys that the layer uses don't reach the host.
- With the layer the root's role is `group` (an `img` hides what is in it from screen readers); its name stays. Each target is `role="button"`, named by a hidden `<title>` in the diagram's `<defs>` (`aria-labelledby`, never `aria-label`: Obsidian's tooltip code throws on SVG elements with one). The name gives the place, never the note, so a drill doesn't give the answer away: "String 5, fret 3", "String 1, open"; "White key 5", "Black key 2" counted from the low end. A mark adds ", right" or ", wrong" to the name.
- Playback: a diagram with a layer is not playable (no `.mn-playable`, no bar): the layer owns clicks and keys. An app that wants to hear a pick plays it itself (the pick's `pitch`).

## Marks

- `layer.mark(at, result)`: `at` is `{ string, fret }` on fretboards, `{ pitch }` on both (every target of the pitch), or a pick as given (its place wins, so it marks its own target); `result` is `right` or `wrong`. Returns false when no target is there. A mark is drawn above the layer, ignoring the pointer (`pointer-events: none`): a filled circle with a check (right) or a cross (wrong), so the shape, not only the color, tells them apart; kept in forced-colors mode. The target gets `mn-pick-right` or `mn-pick-wrong`. A second mark on a target replaces the first.
- `layer.unmark(at)`, `layer.clear()` (every mark), `layer.focus(at?)`, `layer.targets()` (every target as a pick, in document order), `layer.destroy()` (listeners off, marks and tab stops removed, the root's role back to `img`).

## Look

- A target shows only when hovered (a faint accent fill) or focused by the keyboard (an accent stroke inside the cell); the hand cursor on every target (`.mn-pick`, with a class, as #81).
- Colors: `--mn-right` (green, dark enough for a white check in both themes) and `--mn-wrong` (red), set with the other `--mn-` colors. Forced colors: the marks use `Canvas` and `CanvasText`, the focus `Highlight`.

## Also

- `emptyNoteSet(title?)`: a note set with no notes, for a fretboard or keyboard drawn without dots (a drill's empty neck).

## Checks

- Specs first (they fail on 0.14): targets per string × fret (open column, from a fret, a capo from the nut, `strings:`, left hand, vertical), their cells equal the hit areas and never overlap; keyboard targets per key, black on top; attributes and names; no `data-midi`; off by default; picking by click and by keys, the roving tab stop, arrows in every orientation and hand, Home and End; marks, unmark, clear, focus, destroy; `renderBlock` with `pick` (fretboard and keyboard, not playable, destroyed with the block); the press that never reaches the host.
- Chrome: light, dark, keyboard only, a screenshot of each.

## Review (fresh agent) and Chrome check

- Chrome: a Tab landed on the whole diagram, not on its first target: Chromium makes an SVG element with a focus listener a tab stop of its own. The focus listener is now on each target. A mark set from a pick marked every place of its pitch: a place now wins over a pitch.
- Review: marks drawn outside a row's title pad, no picks in popout windows (`instanceof Element`), the #81 cursor spec, the spec's types, no handle on the layers from `renderBlock` and a second attach that doubled everything, the drawing's texts read among the targets, held keys and modifier keys, the white keys' look over the black keys, the look on layers that aren't live, the Business Rules cross-references, the missing specs, presses next to the targets reaching the host. All fixed with specs (`pick.spec.ts`, "review findings").
- Not done: touch events are not stopped (playback does not stop them either); keyboard targets stay at their drawn size on touch screens (black keys 14 units wide).
